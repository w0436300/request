改动清单与理由 — 内部评审用，不属于产品页面。

v4 · Intake details 版式重构

上一版 26 个字段是一条同质的「标签—值」长列，扫读"需求描述"和"成本代码"花一样的力气，细横线分组撑不住这个体量。这次按内容性质拆成两种版式：

  • 短事实 → 三列事实网格（Request / Project / Programme 三卡）：标签小字在上、值在下，密排，1px 网格线分格。一屏能看完过去三屏的信息。
  • 长文本 → 全宽阅读块（Scope of work 一卡）：72ch 行宽，行高放开。交付物渲染成 ✓ 列表、不包含渲染成 ✕ 列表、假设用 • —— 范围的边界一眼可读，这正是这几个字段存在的意义。
  • 右侧粘性区内导航：五个区块可跳转，滚动时自动高亮当前所在区。
  • 信号字段：费用基础为"需要变更单"或"未议定"时显示琥珀色提示块，而不是和其他值长得一样。
  • 编辑态沿用整页编辑：事实网格切成两列输入、列表字段一行一条，校验与"已改动 N 项"保存条不变。

v3 · 本轮改动

  • Actions 菜单从 10 项收到 5 项：只留在列表里就想做、不必打开记录的动作 —— 打开、改状态、指派成员、复制链接，加一条分隔线下的取消。管标签、加工作包、复制为新 intake、导出 PDF 这些都移回详情页，它们本来就需要看到上下文才做得对。详情页的 More 同样收到 4 项。
  • 去掉状态相关的权限门控：行菜单不再按状态置灰，Intake details 也不再因为 Completed / Closed 变只读。状态说明里原来的「谁能改」改成「通常由谁改」—— 保留了解释价值（这是最初的核心需求），但不再断言权限规则。等权限模型定了再加回来，届时置灰 + 悬停说明原因这套交互可以直接复用。
  • 全部人名替换，覆盖列表、通知、评论、活动流、成员表与筛选器。新名单为国际化混合，首字母两两不重复（IO / TV / MK / RO / PR / JV / AN / EH / DA / HL / YT / NB），头像色各自区分，避免演示时误认成真实同事。当前登录用户为 Nadia Brandt。

唯一保留的不可编辑字段是「Raised by」—— 它在提交时写入，属于系统记录而非权限限制，样式上用灰色区分。

v2 · 内容换成建筑 / 工程 / 设计通用语境

原示例是金融业的（Wealth US、IMA Fiduciary、PATRIOT Act），对 AEC 公司不成立。按行业真实结构重做，同时避开英美任一体系的专有名词：

  • 项目 → 工作包两层结构：Fenwick Tower 下挂 Stage 3 图纸包、幕墙计算书。原设计把父级塞进名字里，现在是弱化前缀 + 侧栏 Work packages + 面包屑。
  • 请求类型五类：新项目 / 工作包 / 现场问题 RFI / 变更 / 内部。
  • 新增「项目阶段」维度：Feasibility → Concept → Developed → Technical → Construction support → Handover。不绑定 RIBA 或 AIA，两边的人都读得懂。

顺带解决了一个隐藏的理解问题：项目阶段和 intake 状态是两个维度，"Technical design 阶段"和"In progress 状态"经常被混为一谈。状态说明抽屉顶部有专门的对比说明，FAQ 里也有独立一问。

v2 · Intake details 扩到 26 个字段并可编辑

分五组（细横线 + 小标签分区，不加二级标题）：Request / Project / Scope / Programme & commercial / Files。其中三项是多数系统没有、但工程公司离不开的 ——不包含什么、假设与约束、费用基础（是否需要变更单），这三处是后期扯皮的高发区。软件与格式也单列，模型格式不预先约定是返工的主要来源。

编辑交互：整页进编辑态（工程委托通常一次改一批，逐字段行内编辑反而更慢）→ 必填空值红框 + 字段级提示 → 底部固定条显示"已改动 N 项" → 保存后写进 Activity，Toast 可直接跳转查看改了什么。

沿用 v1 的状态解释体系

四处触达仍在：状态说明抽屉（唯一事实来源，含进入条件 / 流转条件 / 谁能改）、表格与筛选的悬停卡片、改状态下拉里每个选项下的进入条件、详情页顶部的生命周期条。On Hold 与 Cancelled 强制填原因，原因进活动流。

Status guide

Every intake follows the same path. A status only applies once its entry condition is true — that is what keeps the programme report honest.

Status is not the same as project stage

Project stage says where the design is — concept, technical, construction support. Status says where this request is with us. A technical-design job can sit In review for a week before anyone picks it up, and a concept study can be In progress on day one. Both are shown on every intake.

What the NEW badge means

Raised in the last seven days and not yet opened by you. It disappears once you view the intake — it is not a status.

Assign a member

The project lead is notified straight away. Everyone else gets the daily digest.

An intake has one project lead. Assigning a new one replaces the current lead.

Manage tags

Tags group intakes for reporting. They never affect status or permissions.

Cancel this intake?

It stops here and will not resume. The requester and all members are notified. Comments and files stay readable.

Appears on the activity feed and in the monthly report.
